Contexto de Gestión del Sistema

Sistema de administración de inventario farmacéutico en memoria RAM basado en Arreglo de Estructuras (AoS). Implemente los módulos de gestión algorítmica, ordenamiento, filtrado por categoría y cálculo estadístico sobre el stock de medicamentos.

ESPECIFICACIÓN DEL MODELO: 5 Vectores Paralelos (Años Anteriores) Tipos Primitivos Exclusivos

Cada medicamento del inventario está modelado por la estructura Medicamento. Debe declararla en su código fuente utilizando exclusivamente tipos de datos primitivos, deduciendo el tipo apropiado para cada campo según su descripción y rango:

Vector Paralelo Origen Descripción y Regla de Negocio
codigos[] Ingreso de datos Número entero positivo y único (mayor que cero) que identifica a cada lote. No puede repetirse ni modificarse luego del alta.
anioVencimiento Ingreso de datos Año de vencimiento del lote, expresado como número entero entre 2026 y 2035 (inclusive).
categorias[] Calculado Carácter clasificador según la proximidad del vencimiento: 'C' (Crítico) si el lote vence en 2026; 'M' (Medio) si vence en 2027 o 2028; 'E' (Estable) si vence de 2029 en adelante.
preciosLista[] Ingreso de datos Importe numérico con decimales que representa el precio base de lista por caja (debe ser estrictamente mayor que cero).
preciosVenta[] Calculado Importe numérico con decimales resultante según la categoría del lote: 20% de descuento sobre el precio de lista para categoría Crítica ('C'), 10% de descuento para categoría Media ('M'), o precio de lista pleno sin descuento para categoría Estable ('E').
Orden Obligatorio de Miembros en la Estructura: Declare los campos respetando estrictamente el mismo orden en que aparecen en la tabla. Esto es indispensable para que la carga inicial provista en el código base compile sin errores de tipos ni desfasajes.

Alcance del Desarrollo y Diseño Modular

La plantilla base ya incluye las rutinas de visualización por pantalla (mostrarMenu, mostrarFicha y mostrarTabla) y el lote inicial de medicamentos. A partir de los requerimientos funcionales detallados abajo, deberá declarar la estructura de datos con los tipos primitivos adecuados, resolver la interacción con el usuario dentro de las opciones del menú (validando rangos y calculando los atributos derivados) e implementar las operaciones solicitadas.

Reutilización Modular: Cuando una operación necesite localizar un medicamento o verificar si un código ya existe, reutilice la función de búsqueda del punto 1 en lugar de repetir recorridos manuales dentro de otras funciones.

1. Consulta de un Medicamento por Código
10%
Búsqueda por Clave Única
Localización secuencial por código sin modificar los datos, detención inmediata al hallar coincidencia e indicación clara cuando no existe.
  • Objetivo: Localizar un medicamento dentro de los registros activos del inventario a partir de su código identificatorio.
  • Comportamiento esperado: Recorrer únicamente los registros vigentes en modo de solo lectura y detener la búsqueda apenas encuentre la coincidencia.
  • Resultado esperado: Informar la ubicación que ocupa el medicamento encontrado dentro de la colección, o devolver un indicador negativo convencional (-1) si el código no existe.
2. Alta e Inserción en una Posición Determinada
15%
Alta con Unicidad y Resguardo
Control de cupo disponible, validez de la posición elegida, rechazo de códigos duplicados reutilizando la búsqueda y desplazamiento ordenado.
  • Objetivo: Incorporar un nuevo medicamento (con su categoría y precio de venta ya calculados según las reglas del negocio) en una ubicación puntual indicada por el usuario.
  • Resguardos obligatorios: La carga debe rechazarse sin alterar el inventario si ya se alcanzó la capacidad máxima permitida, si la posición indicada está fuera del rango válido de la secuencia actual (negativa o posterior al final vigente) o si el código ya se encuentra registrado.
  • Resultado esperado: Si las validaciones se cumplen, abrir espacio desplazando los elementos posteriores hacia adelante sin perder datos, ubicar allí el nuevo medicamento, actualizar la cantidad activa e informar si la operación se concretó o fue rechazada.
3. Modificación de un Medicamento Existente
15%
Modificación con Clave Inmutable
Localización previa reutilizando la búsqueda, actualización directa de campos editables, recálculo de derivados y clave identificatoria inalterable.
  • Objetivo: Actualizar la información de un medicamento existente a partir de su código identificatorio.
  • Resguardos obligatorios: Si el código buscado no pertenece a ningún registro vigente, debe informarse la ausencia sin modificar el inventario. El código de identificación original debe permanecer estrictamente inalterado.
  • Resultado esperado: Reemplazar únicamente los atributos editables (año de vencimiento, stock en cajas y precio de lista), recalculando automáticamente su categoría y su precio de venta, e informar si la actualización tuvo éxito.
4. Baja Definitiva con Compactación de Datos
15%
Baja Física y Compactación
Localización reutilizando la búsqueda, eliminación real con desplazamiento contiguo para no dejar huecos vacíos y actualización del total activo.
  • Objetivo: Eliminar permanentemente del inventario un medicamento indicado por su código de lote.
  • Resguardos obligatorios: Si el código no existe entre los registros activos, no se debe modificar nada y se informará que no pudo realizarse la baja.
  • Resultado esperado: Al hallarlo, quitarlo y compactar inmediatamente los elementos posteriores desplazándolos una posición hacia atrás para no dejar huecos intermedios, actualizar la cantidad activa de medicamentos e informar el resultado de la operación.
5. Reordenamiento del Inventario (Burbuja Mejorada)
20%
Burbuja Mejorada Ascendente
Implementación manual con detención temprana ante pasadas sin cambios e intercambio completo de registros mediante módulo auxiliar propio.
  • Objetivo: Reorganizar todos los registros activos del inventario en orden ascendente (de menor a mayor) tomando como criterio su precio de lista.
  • Método exigido: Implementar manualmente el algoritmo de Burbuja Mejorada, finalizando anticipadamente si en una pasada completa no resulta necesario efectuar ningún intercambio.
  • Integridad de los datos: Cada permutación debe mover el registro completo con todos sus atributos juntos, delegando el intercambio en un módulo auxiliar propio que trabaje por referencia sobre ambos registros.
6. Filtrado y Visualización por Categoría
10%
Filtrado por Categoría
Consulta de solo lectura que exhibe cada coincidencia aprovechando la vista de ficha provista e informa la cantidad encontrada.
  • Objetivo: Listar todos los medicamentos vigentes pertenecientes a una categoría elegida por el usuario ('C', 'M' o 'E').
  • Comportamiento esperado: Recorrer los elementos activos sin alterar el inventario; por cada coincidencia, invocar la función de ficha individual ya provista en la plantilla base para exhibir sus datos en pantalla y contabilizar los resultados.
  • Resultado esperado: Informar cuántos medicamentos coincidieron con la categoría consultada (o dar el aviso correspondiente cuando no existan coincidencias).
7. Cálculo de Promedio Estadístico por Categoría
15%
Estadística Segura por Categoría
Cálculo de solo lectura sobre la métrica solicitada, protegido frente a inventario vacío o categoría sin registros activos.
  • Objetivo: Calcular el promedio aritmético del precio de venta considerando únicamente los medicamentos activos de la categoría indicada por el usuario.
  • Resguardos obligatorios: La operación no debe modificar el inventario y debe protegerse ante cualquier posibilidad de división por cero: tanto si el inventario estuviera vacío como si no hubiera ningún medicamento activo de la categoría buscada, debe devolver cero (0.0) de forma segura.
  • Resultado esperado: Entregar el promedio en punto flotante para presentarlo en pantalla con dos decimales.

void mostrarTabla(const int codigos[], const int aniosVencimiento[], const char categorias[], const double preciosLista[], const double preciosVenta[], int tam) {
    if (tam == 0) {
        cout << "  [!] El inventario de farmacia esta vacio (tam = 0).\n";
        return;
    }

    cout << "\n+-----+--------+----------+-----+--------------+--------------+\n";
    cout << "| POS | CODIGO | VENCIM.  | CAT | PRECIO LISTA | PRECIO VENTA |\n";
    cout << "+-----+--------+----------+-----+--------------+--------------+\n";

    cout << right;
    for (int i = 0; i < tam; ++i) {
        cout << "| [" << setw(1) << i << "] | "
             << setw(6) << codigos[i] << " |   "
             << setw(6) << aniosVencimiento[i] << " |  "
             << categorias[i] << "  | $"
             << setw(11) << fixed << setprecision(2) << preciosLista[i] << " | $"
             << setw(11) << fixed << setprecision(2) << preciosVenta[i] << " |\n";
    }
    cout << "+-----+--------+----------+-----+--------------+--------------+\n";
    cout << "Total medicamentos en inventario: " << tam << ".\n";
}
